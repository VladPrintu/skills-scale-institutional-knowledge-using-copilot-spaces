# OctoAcme Project Management Docs

This folder contains OctoAcme’s guidance for initiating, planning, delivering, releasing, and improving projects.

## Project management process summary

OctoAcme uses a customer-first, iterative approach with clear ownership and measurable outcomes. Projects begin by validating the business need, aligning stakeholders, and agreeing on success criteria. Approved work is planned into prioritized, estimable increments with acceptance criteria, milestones, and risk or dependency tracking. Teams then manage delivery on a project board, maintain regular communication, and validate quality through reviews, automated tests, and targeted QA. Releases require readiness checks, deployment verification, and rollback planning. Retrospectives capture lessons and convert them into tracked improvements.

Project Managers coordinate delivery, schedules, risks, and communications; Product Managers guide outcomes and priorities; developers and QA deliver and validate the work; and stakeholders provide input and approvals throughout the lifecycle. The process is designed to make work visible, reduce ambiguity, and improve team alignment from idea to production.

## How to use this folder

Use these documents as a shared operating model for OctoAcme work. Start at the project overview and initiation guide when a new project begins, move into planning and execution as work starts, and use the release and retrospective documents to close the loop on delivery and learning.
